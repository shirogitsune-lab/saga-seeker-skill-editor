# ADR 0011: オフラインHTMLガイドと正式スクリーンショットを再生成可能にする

- Status: Accepted
- Date: 2026-07-31

## Context

アプリケーションバージョン 2.0.0 の利用者向け説明は、非エンジニアが
ネットワーク接続なしで読め、配布物とリポジトリの正本がずれない必要がある。
また、Qt の `offscreen` 描画は自動検査には適する一方、Windows 11 の通常表示と
フォント、DPI、テーマ、ウィンドウ枠が異なる可能性がある。

スクリーンショットへ実在のキャラクター名、利用者名、ローカルパス、デスクトップ、
ネイティブファイルダイアログ、SmartScreen の実画面を含めてはならない。

## Decision

### ガイドの正本と配布物

正本を次の構造で直接管理する。

```text
docs/user-guide/
├─ index.html
├─ SCREENSHOT_WORKFLOW.md
├─ SCREENSHOT_AUDIT.md
└─ user-guide-assets/
   ├─ 01-start-screen.png
   └─ ...
```

`index.html` は最初から
`user-guide-assets/01-start-screen.png` のような相対パスを使う。
配布時は本文を変更せず、同一バイトを `使い方.html` としてコピーし、
隣に `user-guide-assets/` をコピーする。

パッケージ処理は配布先の `user-guide-assets/` だけを作り直す。これにより
古い画像を残さず、複数回実行しても同じ入力から同じ結果を得る。
テストでHTMLと画像のバイト一致、相対リンク解決、古い画像の除去、
反復実行の同一性を確認する。

ガイドは単一のオフラインHTMLとローカルPNGだけで構成し、JavaScript、
CDN、Webフォント、外部画像を使わない。日本語システムフォント、16px以上の
本文、意味的な見出し順、スキップリンク、可視フォーカス、狭い画面での
折り返し、`prefers-reduced-motion` を備える。

### 20状態と掲載区分

20状態はすべて再生成可能な正式画像として管理する。本文の手順には主要10状態を
掲載し、残り10状態は補助ギャラリーへ置く。

本文:

1. 起動画面
2. 読込済み画面
3. 基本情報
4. プロフィール比較
5. スキル
6. 性格キーワード
7. 思い出
8. Markdown取込プレビュー
9. 読み取り専用
10. 保存完了

補助ギャラリー:

11. 複数プロフィール展開
12. 比較別ウィンドウ
13. 未使用枠追加
14. 画像変更
15. Markdown書出し
16. 入力エラー
17. ライト
18. ダーク
19. ハイコントラスト
20. ステータス編集

### 自動検査用画像

`QT_QPA_PLATFORM=offscreen` を使用する。20状態すべてについて、必要な状態へ
遷移できること、Qtウィジェットを描画できること、生成画像の幅と高さが0でないこと、
期待する固定サイズであること、既知の個人情報文字列を生成物へ渡していないことを
検査する。これは正式画像そのものではない。

### 利用者向け正式画像

Windows 11 の通常のQtプラットフォーム、表示倍率100%、固定ウィンドウサイズ、
Qt Fusionスタイルで生成する。アプリのウィジェット単体を `QWidget.grab()` で
取得し、デスクトップ全体は撮影しない。ネイティブファイルダイアログは20状態へ
含めない。SmartScreenは文章と合成図解で説明し、個人端末の実画面を掲載しない。

正式20画像は、自動検査とは別に人が目視で次を確認し、
`SCREENSHOT_AUDIT.md` にファイルごとの記録を残す。

- 合成データ以外の人物名・キャラクター名がない
- 利用者名、ホームディレクトリ、ローカルパスがない
- デスクトップ、タスクバー、通知、他アプリがない
- 意図した画面状態で、文字が判読可能である

生成手順は `SCREENSHOT_WORKFLOW.md`、実施結果は `SCREENSHOT_AUDIT.md` に分離する。

### バージョン表記

ガイドでは「アプリケーションバージョン 2.0.0」と
「AI向けMarkdown形式 v2」を別の概念として表記する。
Markdownから新規作成したとき、思い出は件数を検出するが復元しないことを
取込手順と制限事項の両方へ明記する。

## Consequences

- 正本と配布物の本文差分が発生しない。
- 正式画像にはWindows通常表示での生成と目視監査が必要になる。
- 20画像の生成は増えるが、本文は主要10画像に絞って読みやすさを保てる。
- ガイドは外部サービスなしで閲覧できる。
