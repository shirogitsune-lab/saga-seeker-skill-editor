# ADR 0012: ゲーム由来の思い出タグ表現を受け入れる

- Status: Accepted
- Date: 2026-08-03

## Context

思い出は埋込みJSONと、画面表示用の`ul#memories-value`直下の先頭6個の`li`で二重表現される。JSONの`tags`は文字列配列である。一方、ゲームが出力する`data-memory-tags`には`tag1|tag2`というパイプ区切りがあり、既存エディターが生成したHTMLには`["tag1","tag2"]`というJSON文字列がある。

従来の照合はHTML属性をJSON文字列としてだけ解析したため、内容が同じ正常なゲーム出力を不一致と診断して思い出セクションを読み取り専用にしていた。安全機構を一律に緩めると、本当にJSONとHTMLが矛盾するシートを編集可能にする危険がある。

## Decision

JSONの文字列配列を意味上の正本とする。HTML属性は次のいずれかと完全一致した場合だけ正常とする。

1. 属性値が`"|".join(json_tags)`と完全一致するゲーム由来のパイプ形式。
2. 属性値を安全にJSON解析した結果が同じ文字列配列になる既存エディター由来のJSON形式。

パイプ形式を安易に分割しない。これにより、タグ自体に`|`が含まれる場合もJSON側を正本として照合できる。JSON側が文字列配列でない場合、JSON形式が壊れている場合、またはどちらの正常表現とも一致しない場合は不一致とする。

読み込み時に一致した表現種別を各通常思い出へ保持する。既存項目のタグを編集した場合は元の表現種別で属性をパッチし、タグ以外の編集では元のタグ属性バイトを変更しない。新規項目は従来どおりJSON文字列形式で生成する。

未編集レンダリングは入力バイトをそのまま返す。空の思い出配列、厳密な空白保持枠、JSONだけに存在する7件目以降、通常思い出の未知フィールドも既存の位置対応・部分パッチ規則で保持する。

ID、各本文属性、表示タイトル、タグ、プレースホルダー構造、表示スロット数などが実際に矛盾する場合は、従来どおり思い出セクションだけを読み取り専用にする。他の正常セクションの編集可否は変更しない。

## Consequences

- 正常なゲーム出力と既存エディター出力の両方を編集できる。
- 元表現と未編集バイトを維持できる。
- パイプ区切り以外の新しいゲーム表現は自動推測せず、安全側の読み取り専用になる。
- これは思い出タグ属性の互換修正であり、AI向けMarkdown形式 v2や思い出の15件上限を変更しない。
